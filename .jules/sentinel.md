## 2024-05-24 - [Wildcard Injection in PowerShell Cmdlets]
**Vulnerability:** Found wildcard injection vulnerabilities in `find duplicated based on folder.ps1` and `find-duplicated-video.ps1`. When using the `-Path` parameter in cmdlets like `Get-ChildItem`, `Test-Path`, `Move-Item`, and `Get-FileHash`, PowerShell interprets square brackets `[]` and other wildcard characters in filenames. This can cause cmdlets to either fail or act on unintended files if a user-controlled file path contains these characters.
**Learning:** In PowerShell scripts dealing with arbitrary file paths or user input, always use `-LiteralPath` instead of `-Path` to prevent paths from being evaluated as wildcard patterns, avoiding unintended consequences or execution failures.
**Prevention:** Default to using `-LiteralPath` for all path-based cmdlets unless wildcard evaluation is explicitly intended and strictly controlled.
## 2024-03-24 - Directory Scoping Bypass via Path Confusion
**Vulnerability:** Path confusion vulnerability in `find-duplicated-video.ps1`.
**Learning:** Using `String.StartsWith()` for filtering paths without appending a directory separator can unintentionally include similarly named sibling directories. E.g., filtering for `D:\MyFolder` will incorrectly match `D:\MyFolder_Secret\video.mp4`. Furthermore, default `StartsWith()` in .NET is case-sensitive, making it unreliable for Windows file paths.
**Prevention:** Always normalize directory paths by appending a trailing slash (e.g., `TrimEnd('\') + '\'`) and use `[System.StringComparison]::OrdinalIgnoreCase` when comparing paths using `.StartsWith()`.
## 2023-10-29 - Missing Error Handling Exposing Stack Traces
**Vulnerability:** Found a missing error handler in `find-duplicated.py` for the `os.remove()` call. If a file was locked or missing permissions, it would crash the program and expose a stack trace.
**Learning:** File system operations can fail for many reasons outside the program's control. Unhandled exceptions in these operations can leak information about the system through stack traces.
**Prevention:** Always wrap file operations in `try-except OSError` blocks to fail securely, handle the error gracefully, and log a controlled message instead of a stack trace.
## 2024-05-24 - TOCTOU Vulnerability in File Move Operations
**Vulnerability:** Found a Time-of-Check to Time-of-Use (TOCTOU) vulnerability in `find duplicated based on folder.ps1` and `find-duplicated-video.ps1`. When moving duplicate files to a quarantine folder, the scripts used `if (Test-Path)` to check for existence and then `Move-Item -Force` to move the file. This creates a race condition where if a file with the newly generated name is created in the destination between the check and the move, the `-Force` flag will cause `Move-Item` to silently overwrite it, leading to potential data loss.
**Learning:** Checking for file existence before performing an operation is not atomic. In concurrent or multi-process environments, the state can change between the check and the use. Using `-Force` on operations like `Move-Item` can mask this race condition and lead to destructive silent overwrites.
**Prevention:** Use a `while` loop that increments a counter to ensure a unique destination name, and critically, remove the `-Force` flag from `Move-Item` (or use `-ErrorAction Stop`) so that if a collision does happen despite the check, the operation fails safely rather than overwriting data.
## 2024-10-30 - [Information Leakage via Unhandled Exceptions & Predictable File Overwrite]
**Vulnerability:** Found two vulnerabilities in `find duplicated based on folder.ps1`:
1. `Get-ChildItem -Recurse` lacked error handling, causing it to leak sensitive directory structures and permission states to the console/logs when encountering inaccessible (protected/system) directories.
2. The script exported results to a hardcoded, predictable path (`Desktop\DuplicateFilesReport.csv`), creating a risk of symlink attacks or predictable file overwrite.
**Learning:** File system operations scanning wide directory trees must handle permission denied errors securely to prevent information leakage. Additionally, static output paths for reports or logs open systems up to symlink vulnerabilities or data loss.
**Prevention:** Always use `-ErrorAction SilentlyContinue` (or try-catch blocks) when scanning file systems to suppress and securely handle unauthorized access exceptions. Use dynamic, timestamped filenames (e.g., `_$(Get-Date -Format 'yyyyMMdd_HHmmss')`) for generated reports to prevent predictable overwrite vulnerabilities.
